# 数据卡：ERP-fraud-mas（初查）

状态：2026-09-30 完成公开 CSV 的只读字段检查。金额与标签的业务含义仍需以论文和更细粒度数据交叉核验；以下统计不是模型结果。

## 来源与固定版本

- 研究：[Open ERP System Data For Occupational Fraud Detection](https://arxiv.org/html/2206.04460v3)。论文描述用 ERPsim 经营模拟企业，在 ERP 中执行并标记欺诈情境。
- [原始数据提供页](https://www.informatik.uni-wuerzburg.de/datascience/projects/deepscan/erp-fraud-data/)由维尔茨堡大学公开提供 ERPsim 模拟数据下载，说明数据可用于欺诈检测算法开发；页面未见明确的再分发许可证。这里把公开提供与授权再分发分开判断。
- 本次读取的公开镜像：[LSX-UniWue/ERP-fraud-mas 数据目录](https://github.com/LSX-UniWue/ERP-fraud-mas/tree/master/ml-framework/data/erp_fraud)。其 README 指明 `erpsim1.csv` 对应论文 `fraud_2.csv`，`erpsim2.csv` 对应 `fraud_3.csv`。
- 镜像仓库 `master` commit：`d6f5097a5513ff79c1793fd083405c6b1a3ba301`。
- 本次使用 GitHub CLI 以原始内容方式流式读取 CSV；没有把源 CSV 写入本项目目录。

## 标签概况

| 文件 | `NonFraud` 行 | 欺诈行 | 混合正常／欺诈标签的编号 | 已见欺诈标签种类 |
|---|---:|---:|---:|---:|
| `erpsim1.csv` | 36,728 | 50 | 1 | 7 |
| `erpsim2.csv` | 37,321 | 86 | 3 | 7 |

所有记录的 `Belegnummer`、`Label`、`Soll/Haben-Kennz_`、`Betrag Hauswaehr`、`Hauptbuchkonto` 均非空。进一步用实际解析器验收发现 `erpsim1.csv` 有 2 行 `Transaktionsart` 为空；聚合时保留该凭证，只统计非空交易类型。`erpsim2.csv` 未见该字段缺失。本次 CSV 中仅见录入时刻 `Erfassungsuhrzeit`，没有确认完整日期。`Kreditor` 在两份文件中分别有 741／710 行非空；`Material` 有 23,728／24,763 行非空。稀疏字段不能不加判断地用于所有交易类型。

`Belegnummer` 是当前观察到的编号，不代表已验证的独立业务事件。一件欺诈可能对应多个凭证和多行账务；混合标签编号可能来自凭证内不同行的标注，也可能反映其他关联问题。当前复核单位是 `(source_run, Belegnummer)` 候选键，未把它误称为事件 ID。

## 字段语义与聚合检查（Day 2）

`column_information.csv` 将 `Betrag Hauswaehr` 译为本位币金额，将 `Soll/Haben-Kennz_` 译为借／贷标识，将 `Belegnummer` 和 `Position` 列为说明字段。两文件的金额均可解析为十进制数；本次观察到没有零值或负值，因此借／贷不能靠金额正负号判断。

| 文件 | `S` 行 | `H` 行 | 借贷金额按编号不相等的组 | 录入时间格式 |
|---|---:|---:|---:|---|
| `erpsim1.csv` | 17,210 | 19,568 | 0／10,267 | 全部为 `HH:MM:SS` |
| `erpsim2.csv` | 17,352 | 20,055 | 0／10,207 | 全部为 `HH:MM:SS` |

这支持把 `S` 和 `H` 分别聚合，并把借贷平衡当作数据质量检查；**不能**把借贷相抵后的 0 当作交易规模，也不能在缺少币种和金额倍率说明时计算真实货币损失。

两份文件的基础数量单位至少出现 `ST`、`KG` 和空值。数量／金额比只可在同一物料、相同单位且金额语义合适的子集计算，不能把不同单位混合求和。`Kreditor` 等供应商字段只覆盖少数行，先按交易类型检查缺失是否“适用”，再决定是否建模。

`erpsim1.csv` 中混合标签编号有 1 个，`erpsim2.csv` 有 3 个；这些组都同时涉及 `Materialzugang` 与 `Sachkontenbuchung`。可以保留整组行及其标签集合，待复核单位暂定为 `(source_run, Belegnummer)`，标签定义为“组内任一行有欺诈标签”。这只是**候选凭证级目标**，不是独立欺诈事件真值。论文说明一次欺诈可产生多个交易，而当前扁平 CSV 未提供已验证的事件 ID。因此主评估采用完整模拟批次留出，不在同一批次内宣称事件级独立性。[论文数据构建段落](https://arxiv.org/html/2206.04460v3#S4)

## 适用范围与限制

- 论文公开数据用于开发及比较 ERP 欺诈检测方法；这些文件来自模拟经营，不能把结果写成真实客户数据上的效果。
- 论文中有更多情境，但当前聚合 CSV 只覆盖其中可由其所选财务字段识别的部分；留一情境测试以实际标签为准。
- 原始数据页面明确提供下载并介绍其欺诈检测算法用途，但未识别到明确再分发许可证；GitHub 镜像仓库固定 revision 的根目录和文件树也未见许可证。公开仓库与 Databricks 工作区均未上传原始 CSV；工作区私有 UC Volume 仅有无标签的候选单位派生特征。若未来要公开再分发，须另行取得授权或找到适用许可，不能由“公开下载”推断。
- 借贷方向和金额解析已用于探索性结构特征，但具体货币单位／倍率、标签传播的业务真值仍未核验；不得把模型分数解释为实际损失或声称可以付款前预测。
- 为验证解释来源，解析器记录固定哈希 CSV 的数据行号。新版本无标签派生特征 Parquet 包含 `source_lines`（仅行号，不含原始行或标签）；独立核对脚本在本地确认 10,207 个候选单位覆盖 37,407 个源数据行，并复算借贷总额、最大金额、科目和交易类型计数。该文件已在私有 UC Volume 通过上传／下载哈希核对，并由 serverless Job 对 10,207 单位完成评分和唯一键检查；run ID 见进度表。
- 先前已读过论文中的欺诈情境，因此未来规则基线须标注为“领域知情基线”。
- 两个批次共有七个细分欺诈标签；每个标签在外侧批次只有 1–3 个候选阳性凭证。按原始标签移除可以形成压力测试代理，但同一家族变体和未知的跨凭证事件关系无法由该 CSV 排除；不得称为独立新舞弊事件泛化验证。

## 后续仍需核验的问题

1. `Belegnummer` 是否在所有交易类型中代表同一真实凭证，以及是否存在未暴露的公司／年度键；当前用 `source_run` 防止两个文件撞号。
2. 能否从更细粒度原始数据恢复欺诈事件关联；不能恢复时不做事件级 bootstrap。
3. `Betrag Hauswaehr` 的具体单位倍率、公司币种，以及 `Betrag` 在少数行出现时的业务语义。
4. 两个模拟批次有无同源模板或重复结构，会如何影响跨批次评估。
5. 若未来承诺付款前识别，必须先证明每个特征在付款前可得；当前项目不作此承诺。
